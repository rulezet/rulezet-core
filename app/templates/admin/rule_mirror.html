Creating a GitHub token for Rulesets

Rulesets pushes to one GitHub repository per configured entry. Use a fine-grained Personal Access Token scoped to that single repository — never a classic token with account-wide access.

1
Create the destination repository first (if it doesn't exist yet) On GitHub, click New repository. It can be empty — Rulesets will push the first commit itself. Note its owner/name, e.g. your-org/your-rules-mirror.
2
Go to Developer settings In GitHub, open Settings → Developer settings → Personal access tokens → Fine-grained tokens, then click Generate new token.
3
Scope it to the one repository Under Repository access, choose Only select repositories and pick the mirror repository from step 1. Do not grant access to any other repository.
4
Grant it write access to contents Under Permissions → Repository permissions, set Contents to Read and write. Every other permission can stay at No access — Rulesets only ever writes rule files and commits.
5
Set an expiration and generate the token Pick an expiration you're comfortable rotating (e.g. 90 days), then click Generate token. Copy it immediately — GitHub only shows it once.
6
Paste it into the GitHub token field Rulezet stores it server-side and never displays it again once saved — the field will only ever show a masked placeholder afterwards. To rotate it, generate a new token on GitHub and paste it back in here; the old one can then be revoked.
Use a different token for every repository you configure here, and never reuse the token used elsewhere in Rulezet (e.g. GitHub rule import). If a token is ever compromised, revoke it directly from GitHub — Rulezet has no way to do that for you.
