This release is anchored by a full AI integration: a shared agent foundation now powers the Chatbot, a structured Rule Analysis report, a Rule Generator that drafts a rule from a plain description, and a one-shot Rule Fixer, all surfaced through a unified AI admin hub with its own roles and a mascot that shows up across every feature. Alongside that, two new detection formats land (Splunk Security Content and Elastic Security), the Rule Validation false-positive gate introduced in 1.7.1 gets a complete quarantine-review rework, a GitHub Manager role and generic (non-GitHub) git host import round out the import pipeline, and a further nine security fixes close out access-control and injection issues found across proposals, the rule tester, and rendered markdown.

Online version available at [rulezet.org](https://rulezet.org)

## Security

- SSRF via `check_updates_by_rule`'s unvalidated rule source URL is now blocked
- Unauthenticated disclosure of private rule-tester tests is fixed
- A cross-rule IDOR in proposal accept/reject let one user act on another's proposal — now scoped to its owner
- DOM XSS via `document.write` in the MISP graph's raw-JSON view is fixed
- AI-generated markdown now renders through a hardened `SANITIZE_CONFIG` instead of the default one
- The blog page's Markdown renderer (`marked.js`) is now vendored locally instead of loaded unpinned from a CDN
- A cross-entity IDOR in activity-log deletion is fixed
- The MATRIX-ID header impersonation path is removed
- The sanitize fallback now parses untrusted HTML into an inert document instead of operating on it live

We recommend every self-hosted instance upgrade as soon as possible.

## New: AI Integration

A shared AI agent foundation (`ai_core.py` — the Ollama client, agent base class, and a per-agent rate/timeout governor) now backs every AI feature on the platform, replacing the standalone chatbot-only integration from before:

- **Chatbot** — migrated onto the shared foundation, with sharper intent recognition (open-phrase requests turn into structured rule filters), deterministic follow-up questions, and several identity/response fixes
- **Rule Analysis** — a structured report (findings, severity, suggested fixes) instead of a wall of prose, in the same or less time
- **Rule Generator** *(Beta)* — drafts a YARA rule from a plain-language description
- **Rule Fixer** — one-shot "Try AI fix" on the bad-rule edit page, highlighting the broken line and applying a real fix instead of discarding it
- **Unified AI admin hub** — one place to configure and monitor all four agents (model, timeout, rate limit, enabled state) plus a live system-status view, backed by a new **AI Manager** / **AI Operator** role pair so AI configuration and AI usage can be granted independently of full admin
- **Rulezy**, the platform mascot, now shows up across every AI feature with contextual poses and speech bubbles, with a per-instance display toggle for admins who'd rather keep things plain
- A new **How AI Works** page documents the whole pipeline for admins and curious users alike

## New: Rule Validation — Quarantine Review Rework

The false-positive validation gate introduced in 1.7.1 (scan this instance's rules against a known-clean binary baseline, quarantine anything that fires) gets a full review-workflow rework:

- The page splits into **Validation** (launch a run, watch it live) and **History** (every past run, as a table with who launched it and how many rules it quarantined) instead of one mixed view
- Each run gets a **report** — reviewed/pending/disagreement counts and a risk-level breakdown chart, with each figure clickable to filter the rule list straight to it
- A rule already carrying its own risk tag is compared against what this run's baseline scan actually proposes, not a stale sync snapshot — so "Disagrees with rule's own claim" means what it says, and a rule that's already correctly tagged doesn't get flagged as pending forever
- Reviewers get a third option beyond accept-proposed / apply-a-different-tag: **keep the current tag as-is**, explicitly dismissing a disagreement without changing anything
- Accepting or applying a risk tag now removes any conflicting risk tag already on the rule — a rule never ends up carrying two at once
- The quarantine list opens on "pending only" by default, with risk-level and binary filters, bulk actions, and a "select all matching" control that actually selects everything matching the filter, not just the current page

## New: Splunk Security Content & Elastic Security Formats

Two more detection formats join YARA, Sigma, Suricata, CRS, Wazuh, and ATR:

- **Splunk Security Content** — YAML detections with the SPL query in a `search` field; validation also recognizes the pre-refactor `removed/` detections that predate Security Content's current schema, instead of flagging ~700 legitimate historical detections as invalid
- **Elastic Security** detection rules, including its query languages (KQL/EQL/ES|QL — corrected from an initial `kuery` enum mismatch)

## New: GitHub Manager Role & Generic Git Host Import

- A **GitHub Manager** role can now be granted import/update/sync/proposal rights over the GitHub rule pipeline without full admin access
- Importing from a **non-GitHub git host** is now supported, alongside a configurable `GITHUB_HOST` for self-hosted GitHub Enterprise instances
- The proposal accept flow is unified into a single import-then-transfer path, fixing a class of edge cases where the two steps could disagree

## Also New

- **Proposal revisions & discussion feed** — rule edit proposals now keep a revision history and a GitHub-style comment thread, with `@mention` notifications
- **Notifications rework** — a dedicated "Jobs" tab in the bell, reworked filters and read-state handling, and a fix for "Mark all read" being hidden whenever only job notifications were unread

- Suricata syntax highlighting for CodeViewer/SmartEditor
- New indexes on rule_id foreign-key columns, speeding up permanent trash deletion

- The trash page's format filter now loads dynamically instead of a hardcoded list
- Blog post editor: fixed broken tag selection and cover-image upload
